Licensing Intelligence MCP

A proof-of-concept MCP server that exposes MathWorks licensing & entitlement data to AI agents — with role-gated write tools, audit logging, and a custom agent host.

What Is This Project?

This is a local proof-of-concept that demonstrates how AI agents can interact with enterprise licensing systems through the Model Context Protocol (MCP) — an open standard by Anthropic that gives agents structured, typed access to external tools and data.

Instead of building a chatbot wrapper, this project creates a governed capability surface where:

  • Each tool maps to a well-defined domain operation
  • Write actions are audited with full reasoning chains
  • Access is role-scoped from the ground up (CS-L1, CS-L2, CS-L3)

Two Agent Personas, One Server

Query Agent (Read Surface)

Open access. Answers "what is the current state of X?" — license status, entitlements, seat counts, products.

6 read tools

CS Action Agent (Write Surface)

Role-gated. Every write is audited. The agent proposes actions; actions execute under a CS rep's verified identity.

7 write tools 3 role tiers

Layered Design

The codebase is organized into clean layers with strict dependency direction (top calls down, never up):

LayerFilesResponsibility
Interfacetools/*.py, prompts.pyMCP tool definitions — descriptions, schemas, error shaping. Delegates all logic downward.
Pipelinecs_executor.py, identity.pyWrite pipeline: resolve identity → role gate → mutate → audit → atomic commit
Data Accessdata_access/*.pySQLAlchemy queries. In production, this becomes authenticated HTTP calls to microservices.
Foundationmodels.py, database.pyORM models (17 tables), session factory, DB path configuration

Key Design Principle: Isolation of Data Access

The data_access/ layer is the ONLY code that knows how data is fetched. In the POC it's SQLAlchemy queries; in production it becomes signed HTTP calls to microservices. The tool layer above never changes:

# POC — direct SQLAlchemy query
def get_license(license_id: str, db: Session) -> dict:
    return db.query(License).filter(License.id == license_id).first()

# Production — signed call to the Licensing microservice
def get_license(license_id: str) -> dict:
    token = sign_service_token(private_key=MCP_PRIVATE_KEY, audience="licensing-service")
    headers = {"Authorization": f"Bearer {token}"}
    return httpx.get(f"{LICENSING_API}/v1/licenses/{license_id}", headers=headers)

Transport: stdio over JSON-RPC 2.0

The MCP server runs as a subprocess of the client (Claude Desktop or the custom agent host). Communication flows over stdin/stdout as JSON-RPC 2.0 messages. There is no network port, no TLS — process isolation IS the security boundary for the POC.

In production: swap to Streamable HTTP transport with OAuth 2.1 bearer tokens on every request.

What Is MCP?

The Model Context Protocol (MCP) is an open standard by Anthropic that allows AI agents to securely access external tools and data. Think of it as "REST APIs for agents" — a typed interface contract between an AI consumer and a capability provider.

MCP has three primitives:

PrimitiveInvoked ByPurpose
ToolsThe model (AI)Actions the agent can call — like function calls
ResourcesThe applicationContext attached by the client app (not used here)
PromptsThe userConversation starters from a menu — pre-built workflows

Server Entry Point: server.py

The entry point's only job is to import tool modules (which triggers registration via @mcp.tool() decorators) and then run the server. Adding a new tool = adding one import line.

# Tool registrations — importing triggers @mcp.tool() decorator
from licensing_mcp.tools import get_license_status          # noqa: F401
from licensing_mcp.tools import check_user_entitlements     # noqa: F401
# ... 11 more imports ...

from licensing_mcp.server_instance import mcp

def main():
    mcp.run(transport="stdio")

MCP Prompts: prompts.py

Two user-invocable prompts appear in Claude Desktop's "+" menu. They inject a structured instruction as the user's message, which then drives multi-step tool calls:

PromptWhat It Does
license_health_reviewFull account health check — pulls all licenses, flags expiring/over-capacity/under-used ones
diagnose_activation_issueCS Tier-1 diagnostic workflow: check entitlements → check seats → find stale activations → propose fix

Elicitation: elicitation.py

MCP supports server-driven confirmation forms — the server can ask the user to confirm before executing a destructive action. The ElicitationBase class sanitizes Pydantic schemas to comply with MCP's restriction that elicitation fields must be flat primitives (no unions, no null defaults).

Used by revoke_activation to show the rep exactly what will be revoked before executing.

Tool Anatomy: revoke_activation.py (Example)

This is the most complex tool — it demonstrates elicitation (confirmation), the executor pipeline, and graceful fallback for clients that don't support forms:

@mcp.tool()
async def revoke_activation(user_email, product_name, machine_id, reason, confirm=False):
    # 1. Read-only lookup for confirmation context
    details = find_activation(session, user_email, product_name, machine_id)

    # 2. If client supports elicitation → show confirmation form
    if client_can_elicit:
        response = await ctx.elicit(message="Confirm revocation: ...", schema=ConfirmRevocation)
        if not confirmed: return {"cancelled": True}
    # 3. Fallback: return details, ask human, caller calls again with confirm=true
    elif not confirm:
        return {"confirmation_required": True, "details": details}

    # 4. Execute through the write pipeline (identity → gate → mutate → audit)
    return execute_cs_write(tool_name="revoke_activation", reason=reason, mutate=...)

The CS Write Executor: cs_executor.py

This is the security centerpiece. Every write tool funnels through one function — execute_cs_write(). This guarantees the critical sequence is never forgotten:

1
Resolve Identity — read CS_ACTOR_ID, look up the user and their highest role
2
Permission Gate — check if the actor's role is granted this tool in cs_permissions table. Rejections are audited.
3
Mutate — execute the domain operation (passed as a closure). Captures before/after state.
4
Audit — write the audit record in the SAME transaction as the mutation
5
Atomic Commit — one session.commit() covers both mutation + audit. If either fails, both roll back. An unaudited write is structurally impossible.

Identity Resolution: identity.py

Identity is resolved per call, never cached. Three functions:

FunctionWhat It Does
resolve_actor(session)Reads CS_ACTOR_ID env var, looks up user + highest role in DB. Returns {id, email, name, role, level}.
has_permission(session, actor, tool)Checks if the actor's role has a grant for this tool in cs_permissions table.
minimum_role_for(session, tool)Returns the lowest role that CAN call this tool — used in rejection messages for clear escalation guidance.

Production Security Architecture

The project includes a comprehensive security document covering the full production posture:

Auth Boundary 1: User → MCP Server

  • OAuth 2.1 + PKCE via PingID
  • Group-gated access (e.g., "MCP-LicensingTool-Approved")
  • JWT with role claims (cs_tier)
  • Adding/removing users = IdP group change (no deploy)

Auth Boundary 2: MCP Server → Microservices

  • Asymmetric key-based service auth (RFC 7523)
  • MCP server signs requests with its private key
  • Microservices verify with registered public key
  • Standard service onboarding process

Custom Agent Host (agent/)

Beyond Claude Desktop, the project includes a custom agent host — a FastAPI web server with Keycloak OIDC login, a chat UI, and a per-user MCP bridge. This demonstrates that the MCP server is client-agnostic and that the auth boundary lives in the host layer.

Browser → /login → Keycloak → /callback → session cookie Browser Chat UI → POST /api/chat (cookie) → Agent Loop → Claude Sonnet ↓ tool calls per-session MCPBridge(actor_email) ↓ CS_ACTOR_ID=email licensing-mcp (stdio subprocess)

Component Breakdown

auth.py — JWT Validation

  • Fetches Keycloak JWKS (public keys) — cached with lru_cache
  • Validates JWT: signature, issuer, expiry
  • Extracts email claim → becomes CS_ACTOR_ID
  • Single responsibility: prove who the user is

app.py — FastAPI Server

  • GET /login — redirect to Keycloak (with &prompt=login)
  • GET /callback — exchange auth code → JWT → session cookie
  • GET /logout — stop bridge, clear session, redirect home
  • POST /api/chat — cookie-gated; lazy-starts bridge on first message
  • POST /api/chat/reset — clears message history (New Chat)
  • GET /api/tools — also the frontend auth probe (returns 401 if not logged in)

mcp_bridge.py — MCP Client

  • One bridge per authenticated session (not one global bridge)
  • Constructor takes actor_email; sets CS_ACTOR_ID env var on the subprocess
  • Spawns python -m licensing_mcp as a stdio subprocess
  • Converts MCP tool definitions → Claude API format (one field rename)
  • call_tool(name, args) — executes a tool and returns text

static/index.html — Chat UI

  • On load: calls /api/tools — shows login overlay on 401
  • Login overlay: "Sign in" button → /login
  • Header shows authenticated user's email + Sign out link
  • New Chat calls /api/chat/reset (clears server-side history)

The Agent Loop: agent_loop.py

A hand-rolled agentic loop that does what Claude Desktop does internally. One user turn may require multiple API round-trips:

1
Send conversation + tool definitions to Claude API
2
Check stop_reason: if "end_turn" → done. If "tool_use" → step 3
3
Execute each tool call via the MCP bridge
4
Append assistant content + tool_result blocks to history
5
Loop back to step 1 (max 15 iterations as circuit breaker)

Key details:

  • Uses claude-sonnet-4-6 model with adaptive thinking
  • Prompt caching (cache_control: ephemeral) reduces cost by ~90% on repeated prefixes
  • Assistant turn content is appended VERBATIM (tool_use blocks must stay for ID pairing)
  • System prompt guides the agent to diagnose before acting, write full justifications, and get confirmation before destructive actions

Stopping

# Stop the agent host
Ctrl+C in Terminal 2

# Optionally stop Keycloak (data persists in the container)
docker stop licensing-keycloak

Keycloak data (realm config, users) survives container stop/start. To start fresh, docker rm licensing-keycloak and re-run the setup from Part 1 of the Keycloak guide.
